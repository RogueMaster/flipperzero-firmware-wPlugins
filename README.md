# TPMS Renault 433 МГц через Flipper Zero

Чтение датчиков давления в шинах Renault (433.92 МГц, например 407003VU0B)
на компьютере. Flipper Zero работает радиомодулем и подключается по USB.

Состоит из двух частей:

* **`flipper/tpms_bridge`** — приложение для Flipper Zero. Настраивает CC1101
  на 2-FSK, принимает эфир, декодирует кадры Renault и печатает их построчным
  JSON в CLI, то есть в USB.
* **`host/`** — приложение для компьютера на Python + PySide6: таблица
  датчиков, графики давления и температуры, экспорт CSV, разбор записей
  офлайн.

## Почему нужно приложение на Flipper, а не только CLI

Штатной прошивкой этот датчик по USB не прочитать:

* `subghz rx_raw` жёстко загружает OOK-пресет
  (`subghz_device_cc1101_preset_ook_270khz_async_regs`), а `subghz rx` —
  `FuriHalSubGhzPresetOok650Async` и декодирует только протоколы пультов.
  Датчик передаёт FSK, через OOK-демодулятор его не видно.
* Запись `.sub` через **Sub-GHz → Read RAW** тоже не подходит: RAW-декодер
  выбрасывает импульсы короче `te_short = 50` мкс
  (`lib/subghz/protocols/raw.c`), причём выбрасывает без слияния с соседним
  интервалом — переход просто исчезает. У Renault длительность чипа как раз
  ~50–52 мкс, так что поток разваливается. В Unleashed и Momentum порог тот же.

Поэтому демодуляция и разбор идут на самом Flipper, а по USB уходят уже
готовые кадры.

## Протокол

Сверено с [rtl_433 `tpms_renault.c`](https://github.com/merbanan/rtl_433/blob/master/src/devices/tpms_renault.c)
и [ProtoView `renault.c`](https://github.com/antirez/protoview/blob/main/protocols/tpms/renault.c):

| Параметр | Значение |
|---|---|
| Модуляция | 2-FSK, 433.92 МГц, чип ~50 мкс (~20 kBaud) |
| Кодирование | Manchester, конвенция плавает — см. ниже |
| Преамбула + sync | `55 55 55 56`, в чипах `01010101010101010110` |
| Кадр | 9 байт (144 чипа после sync) |
| Контроль | CRC-8, poly `0x07`, init `0x00`, по первым 8 байтам |

**Про полярность.** Демодулятор может отдать поток любой полярностью, и —
что выяснилось на живом датчике 407003VU0B — полярность sync-слова не
обязана совпадать с конвенцией Manchester в данных: sync пришёл прямой, а
пары данных инвертированные. Поэтому декодер перебирает то и другое
независимо, все четыре сочетания, и принимает то, на котором сходится CRC.
Перебор полярности «целиком», как в референсах, этот датчик не ловит.

Поля:

```
flags        = b[0] >> 2
pressure_kPa = (((b[0] & 3) << 8) | b[1]) * 0.75
temperature  = b[2] - 30          (°C)
id           = b[5]<<16 | b[4]<<8 | b[3]      (little-endian, 24 бита)
unknown      = b[7]<<8 | b[6]     (обычно 0xFFFF)
crc          = b[8]
```

Пресет CC1101 (2-FSK, 20 kBaud, девиация 28.56 кГц, полоса 325 кГц) взят из
ProtoView — он проверен на реальных датчиках.

## Установка

### Приложение для Flipper

Нужен [ufbt](https://github.com/flipperdevices/flipperzero-ufbt). Собрано и
проверено на официальной прошивке 1.4.3 (API 87.1), используется новый
CLI API (`cli_registry_add_command_ex`).

```sh
python3 -m pip install --upgrade ufbt
ufbt update                       # канал release

cd flipper/tpms_bridge
ufbt                              # собрать -> dist/tpms_bridge.fap
ufbt launch                       # собрать, залить на Flipper и запустить
```

### Приложение для компьютера

```sh
cd host
python3 -m pip install -r requirements.txt
```

## Как пользоваться

1. Запустить на Flipper **Apps → Sub-GHz → TPMS Bridge**. Приложение должно
   оставаться открытым: пока оно закрыто, команды `tpms_rx` в CLI нет.
2. Запустить приложение на компьютере:

   ```sh
   cd host
   python3 -m tpms.app
   ```

3. Выбрать порт (ищется сам), включить галочку **Будить** и нажать
   **Подключить**.
4. Положить датчик вплотную к **задней стороне** Flipper — там катушка
   125 кГц.

Датчик в покое молчит: он выходит в эфир от вращения колеса или от
низкочастотного поля, как от штатного прибора активации. С галочкой
**Будить** Flipper излучает поле импульсами по 0.7 с каждые 5 с, приём при
этом не прерывается — датчик отвечает сразу. Ту же активацию делает кнопка
**Right** на самом Flipper.

Показания появляются в таблице; выбранный датчик рисуется на графике.
Кнопка **Экспорт CSV…** выгружает все принятые кадры.

Проверено на датчике 407003VU0B: 51 кадр за 25 секунд, ID `02c99d`,
26 °C, давление около нуля — датчик лежал на столе, а не стоял в шине.

### Консольный режим

Без окна, тем же кодом:

```sh
python3 -m tpms.console --wake                # слушать эфир, будить датчик
python3 -m tpms.console --wake --csv out.csv  # и выгрузить в CSV
python3 -m tpms.console --mode raw --wake     # сырые тайминги
python3 -m tpms.console --decode capture.sub  # разобрать файл офлайн
```

### Прямо в CLI Flipper

```
tpms_rx                            # 433.92 МГц, JSON
tpms_rx 433920000 json wake        # с пробуждением датчика
tpms_rx 433920000 raw wake         # сырые тайминги для диагностики
```

Каждый кадр — одна строка:

```json
{"t":123456,"proto":"renault","id":"7ad779","raw":"d9453479d77affffbf","pressure_kpa_x100":24375,"temp_c":22,"flags":54,"unknown":65535,"rssi_dbm_x10":-625}
```

Числа целые: `printf` прошивки не обязан уметь `%f`. Поля на компьютере
пересчитываются заново из `raw` — `host/tpms/decoder.py` остаётся
единственным источником правды по протоколу.

Остановка — `Ctrl+C`.

## Если кадры не ловятся

1. Проверить, что включено пробуждение и датчик лежит вплотную к задней
   стороне Flipper. Без этого он молчит.
2. `tpms_rx 433920000 raw wake` или режим **raw** в UI — пойдут сырые
   тайминги. Ответ датчика видно как пачку из ~130 импульсов, где подряд
   идут значения около 50 мкс.
3. Если таких пачек нет — датчик не просыпается или частота другая.
4. Если пачки есть, а кадров нет — протокол отличается. Сохранить лог
   кнопкой **Сохранить лог…**, потом разбирать офлайн через
   **Открыть .sub / дамп…** или `--decode`. Менять придётся только
   `host/tpms/decoder.py`, прошивку пересобирать не нужно.

Экран приложения на Flipper: **OK** включает локальный приём (показания
прямо на Flipper, без компьютера), **Right** — импульс пробуждения,
**Back** — выход. Радиомодуль занимает кто-то один: либо локальный приём,
либо USB-сессия.

## Ограничения

* Пока приложение открыто на Flipper, оно занимает экран. Закрывается и
  снаружи: `loader close` или `ufbt launch` — приложение обрабатывает
  сигнал выхода.
* Одновременно работает одна сессия приёма. Вторая получит
  `{"error":"radio busy"}`.
* Если хост перестал читать поток и не закрыл команду, сессия сама
  завершится через 5 секунд и освободит радиомодуль.
* `raw`-режим ограничен 200 000 интервалов на сессию: FSK-шум идёт
  сплошным потоком и без ограничения забивает канал.

## Тесты

```sh
cd host && python3 -m pytest -q          # 51 тест, железо не нужно
cd flipper/decoder_test && ./run.sh      # декодер прошивки на хосте
```

Оба набора гоняют один и тот же тестовый вектор из ProtoView
(ID `7ad779`, 243.75 кПа, 22 °C), проверяют CRC, все сочетания полярности
(включая то, что даёт реальный датчик), устойчивость к джиттеру ±15% и
отбраковку битых кадров. Реальный кадр с 407003VU0B зафиксирован в тестах
как регрессия.

## Структура

```
flipper/tpms_bridge/     приложение для Flipper (C, ufbt)
  tpms_bridge.c          экран, регистрация CLI-команды, локальный приём
  tpms_cli.c             команда tpms_rx: JSON и raw
  tpms_session.c         CC1101, асинхронный приём, буфер интервалов
  tpms_renault.c         чипы -> Manchester -> CRC -> поля
  tpms_lf.c              поле 125 кГц для пробуждения датчика
  tpms_preset.h          регистры CC1101
flipper/decoder_test/    прогон того же декодера на компьютере
host/tpms/
  decoder.py             декодер и генератор кадров
  flipper_link.py        USB CLI: команда, разбор NDJSON
  model.py               накопление по датчикам, экспорт CSV
  sub_file.py            офлайн-разбор .sub и raw-дампов
  ui/                    окно и график
  app.py, console.py     точки входа
host/tests/              тесты
```
